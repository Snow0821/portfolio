# Python Intro Discussion

## Purpose

프로그래밍이 어렵게 느껴지는 이유와 파이썬이 입문과 작은 실험의 장벽을
어떻게 낮추는지 설명하고, 기초 문법을 실제 활용과 한계까지 연결한다.

## Audience

프로그래밍 경험이 없거나 매우 적은 비전문가를 대상으로 한다. 특정 운영
체제, 편집기 또는 수학 지식을 선수 조건으로 두지 않는다.

## Core question

파이썬은 어떤 선택으로 프로그래밍의 첫 장벽을 낮추며, 그 선택은 언제
유용하고 언제 한계가 되는가?

## Must cover

- 자연어 설명을 정확한 절차로 바꾸는 프로그래밍의 진입 장벽
- C와 Java의 명시적 타입·도구 흐름이 주는 장점과 파이썬의 다른 균형
- 읽기 쉬운 문법, 값과 기본 데이터 구조, 들여쓰기
- 조건문, 반복문과 함수가 판단·반복·재사용을 표현하는 방법
- 자동화, 웹, 데이터, AI 활용 사례
- 런타임 타입 오류, 성능과 생태계 선택의 한계

## Out of scope

- 고급 패키징과 배포 체계
- 비동기 프로그래밍 심화
- Django, FastAPI 등 특정 프레임워크 튜토리얼
- C나 Java가 파이썬보다 열등하다는 단정

## Example and evidence candidates

- 이름, 나이, 기술 목록과 프로필 사전을 함께 쓰는 현재 기초 예제
- 반복 파일 작업을 짧은 스크립트로 줄이는 전후 비교
- 같은 문제를 정적 타입 언어와 비교할 때 도구 단계와 오류 발견 시점을
  함께 설명하는 균형 잡힌 사례

## Decisions

- 현재 자료는 변수, 기본 데이터 구조, 제어 흐름과 함수까지를 기초 범위로
  삼는다.
- C와 Java는 이전의 열등한 방식이 아니라 다른 예측 가능성과 도구 지원을
  선택한 비교 대상으로 설명한다.
- 활용 분야는 가능성을 보여주되 각 프레임워크 사용법으로 확장하지 않는다.
- 이 문서의 초기화 작업은 승인된 런타임 콘텐츠를 다시 쓰지 않는다.

## Open questions

- `확인`: 첫 실습을 현재 프로필 예제로 유지할지, 입출력이 더 분명한 작은
  자동화 예제로 바꿀지 다음 Python 콘텐츠 작업에서 논의한다.
- `확인`: 함수 설명에 입력·출력 개념을 보여주는 두 번째 예제가 필요한가?
  추가 시 읽기 자료와 발표 자료의 정보 밀도 영향을 함께 검토한다.
