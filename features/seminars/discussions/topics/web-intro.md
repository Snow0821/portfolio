# Web Intro Discussion

## Purpose

인터넷과 웹의 차이에서 출발해 사용자의 URL 입력이 브라우저 화면과 웹
애플리케이션으로 이어지는 흐름을 설명한다.

## Audience

웹을 사용하지만 네트워크나 개발 경험은 없는 비전문가를 대상으로 한다.
터미널, 서버 운영 또는 특정 프레임워크 경험을 가정하지 않는다.

## Core question

연결된 컴퓨터 위에서 웹은 어떤 공통 약속으로 문서와 애플리케이션을 찾고,
전달하고, 화면에 표현하는가?

## Must cover

- 인터넷은 연결망이고 웹은 그 위의 정보 체계라는 구분
- URL, DNS, HTTP와 클라이언트·서버 요청/응답 흐름
- HTML 구조, CSS 표현, JavaScript 상호작용의 역할
- DOM과 CSSOM, 레이아웃과 페인트로 이어지는 브라우저 렌더링
- 공개 문서, 대화형 애플리케이션과 API 활용
- 보안, 성능, 호환성, 접근성과 변화하는 도구 생태계의 한계

## Out of scope

- React, Vue 등 특정 프레임워크 튜토리얼
- 라우팅, 방화벽, 인증서 운영 등 심층 네트워크 관리
- 브라우저 엔진 내부 구현의 세부 알고리즘
- 웹이 기존 인터넷 도구를 모두 대체했다는 단정

## Example and evidence candidates

- URL 입력부터 DNS 조회, HTTP 응답, 렌더링까지의 한 장 흐름도
- 현재 HTML/CSS 카드와 시맨틱 HTML 예제
- 문서 요청과 API 데이터 요청이 공유하는 클라이언트·서버 구조 비교

## Decisions

- 인터넷과 웹을 같은 말로 사용하지 않고 계층 관계를 먼저 설명한다.
- HTML/CSS/JavaScript는 구조·표현·상호작용의 역할 구분을 중심으로 다룬다.
- API와 웹 애플리케이션은 문서 중심 웹의 확장 사례로 소개한다.
- 이 문서의 초기화 작업은 승인된 런타임 콘텐츠를 다시 쓰지 않는다.

## Open questions

- `확인`: DNS와 HTTPS를 한 흐름도에 함께 표시하면 입문자에게 과밀한지
  다음 Web 콘텐츠 작업에서 검토한다.
- `확인`: 접근성을 렌더링 설명 안에 둘지 열린 웹의 책임 부분에 둘지,
  두 표현의 이해 순서를 비교해 결정한다.
