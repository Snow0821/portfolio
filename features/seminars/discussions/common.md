# Shared Seminar Discussion

## Audience assumptions

- 대상은 전문 배경지식이 없는 관심 있는 비전문가다.
- 용어를 처음 사용할 때 일상 언어로 뜻과 역할을 설명한다.
- 선수 지식이 필요하면 암묵적으로 가정하지 않고 자료에 명시한다.

## Explanatory depth

- 문제, 이전 접근, 핵심 방법, 활용 사례, 결론과 한계를 함께 다룬다.
- 방법 설명을 중심에 두되 맥락이나 한계를 시간 절약을 이유로 제거하지
  않는다.
- 입문 자료의 목표는 도구 사용법을 모두 나열하는 것이 아니라, 독자가
  핵심 흐름과 선택 기준을 자기 말로 설명하게 하는 것이다.

## Shared-source projection rules

- 읽기 자료와 발표 자료는 하나의 주제 데이터를 공유한다.
- 읽기 자료는 전체 내용을 연속 문서로 보여준다.
- 발표 자료는 같은 블록을 한 가지 설명 목적의 슬라이드로 선택·배치한다.
- 표현별 레이아웃은 달라도 사실, 용어, 예제의 의미가 충돌하면 안 된다.

## Evidence and example standards

- 비교는 우열 단정 대신 각 접근의 목적과 trade-off를 함께 설명한다.
- 예제는 핵심 개념을 드러내는 최소 크기로 유지하고, 코드가 무엇을
  보여주는지 캡션이나 주변 문장에서 설명한다.
- 외부 사실과 이미지는 출처, 최신성, 사용 권리를 확인한다.
- 작성 중 마찰이나 이해도 피드백은 규약 개선의 근거로 기록한다.

## Decisions

- 현재 공통 형식은 `introductory-60`이며 숫자 60은 강제 시간·분량 제한이
  아니다.
- 다섯 의미 역할은 `problem`, `prior-art`, `method`, `cases`,
  `conclusion` 순서를 유지한다.
- 논의 문서는 런타임 소스가 아니며 합의된 변경만 형식 또는 데이터에
  반영한다.

## Open cross-topic questions

- `확인`: 발표 현장에서 독자의 선수 지식을 빠르게 확인할 공통 질문이
  필요한가? 영향은 도입부 길이와 진행 방식이며 다음 콘텐츠 작업 전에
  논의한다.
- `확인`: 외부 통계나 역사적 사례에 적용할 공통 최신성 기준은 어느
  수준이 적절한가? 실제 외부 근거를 추가하는 작업에서 결정한다.
