# 변환 품질 검수 기록

## 기준
UI에서 수정하지 않고 HWPX를 내려받아 한글에서 수정한다. 유료/사용량 제한이 있는 LLM API를 연결하지 않는다. 예제의 원본 사진과 본문은 공개 저장소에 넣지 않는다.

검증은 세 단계로 구분한다.
1. 처리 로직: 단 경계, 읽기 순서, 문단 분리, HWPX 구조.
2. 원본 일치: 공백 포함/제외 문자 오류율(CER), 문항·선지 누락, 그림 순서.
3. 한글 렌더링: 표·그림·단/쪽 경계, 미주 위치, 글자 겹침.

OCR confidence를 정확도나 기준 전사 대용으로 사용하지 않는다. 신뢰도가 낮다는 이유로 문장을 삭제하거나 답을 추측하지 않는다.

## 2026-09-30 — pipeline 2026-09-30.1

확인한 코드 문제:
- preserve_interword_spaces=0. 이전 세션에서 실제 사진과 합성 예제 모두 한글 공백 분리가 재현되었다.
- 업로드에서 긴 변 3,000px 축소 + JPEG 재압축, 인식 전 추가 디코딩.
- 사진 너비의 50%를 고정 경계로 사용. 원본의 단 위치가 어긋나면 글자가 잘린다.
- 하나의 OCR 문단 안에서는 큰 공백이나 그림을 사이에 두어도 일반 텍스트를 합친다.
- 선지 기호가 @로 읽히면 발문에 붙는다.
- 줄바꿈된 정상 선지는 오히려 별도 문단으로 끊어진다.
- 읽기 설정을 바꿔도 이미 인식한 결과가 무효화되지 않는다.

수정:
- 공백 보존 1, 원본 바이트 유지, 인식 입력 최대 4,400px, 회전 PNG.
- 중앙 공백 띠 탐색, 얇은 구분선 제외, 근거가 부족한 경우 명시적 fallback.
- 줄 간격과 새 지문 경계로 병합 제한, 선지 연속 문장 유지. @ 문자 자체는 보존.
- 설정 변경 시 재변환을 요구하고 이전 결과 다운로드를 막음.
- 사진을 담지 않는 진단 JSON과 개선 전후 비교 도구 추가.
- UI를 사진/미리보기/하단 행동 버튼으로 정리. 고급 설정은 접힌 상태.

실행한 검증:
- 16개 합성/구조 회귀 검사: 통과. 내용은 tests/regressions.mjs.
- JS 구문 검사 및 HTML ID 연결 검사: 통과.
- 기존 HWPX 구조 검사는 Vercel 배포 명령에서 다시 실행한다.

아직 완료하지 못한 검증:
- 이번 세션의 작업 실행 환경이 unavailable이며 Drive 파일 본문 읽기가 transport/dispatch 오류로 실패했다.
- 따라서 예제 사진 6장의 개선 전후 OCR 재실행, CER, 누락 수는 **미측정**.
- 새 UI의 데스크톱/모바일 브라우저 실화면 검증도 **미완료**.
- 한컴 한글에서 최신 HWPX를 렌더링한 결과도 **미검증**.
- 회귀 검사 통과를 실제 사진 정확도 개선 수치로 보고하지 않는다.

## 다음 실제 사진 검수
1. 동일한 원본 사진·방향·그림 영역을 고정하고 현재 버전 진단 JSON을 저장한다.
2. 사진을 직접 읽어 만든 기준 전사를 페이지별로 만든다. 제공된 HWPX는 참고하되 사진과 다를 수 있는 부분은 원본을 우선한다.
3. 한 가지 원인만 수정해 같은 입력을 다시 실행한다.
4. CER뿐 아니라 문항 번호·①~⑤·보기·그림 누락을 비교한다.
5. 문제 사진에서 개선되고 다른 사진에서 퇴행하지 않을 때 유지한다.
6. 마지막으로 HWPX를 한글에서 PDF로 저장해 본문·표·그림·미주 배치를 확인한다.

원본 일치 목표: 문항/선지/그림 누락 0. CER 목표는 첫 실제 기준 측정 후 설정한다. 목표를 달성하기 전 '정확하게 옮김'이나 '검수 완료'라고 표기하지 않는다.

## 비교 도구
변환 설정 → 변환 기록 저장으로 만들어진 파일과 기준 JSON을 사용한다.

~~~json
{
  "pages": [
    {
      "name": "example.jpg",
      "text": "1. 속력에 대한 설명으로 옳은 것은?\n① 단위 시간 동안 이동한 거리이다.",
      "questionNumbers": [1],
      "choiceMarkers": 1,
      "figures": 0
    }
  ]
}
~~~

~~~sh
node ocr-app/scripts/compare.mjs reference.json before.diagnostics.json after.diagnostics.json
~~~

이름이 같은 페이지끼리만 비교하며, 빠진/추가된 페이지를 따로 표시한다. 중복 파일명은 비교를 중단한다. 출력 CER은 작을수록 좋고, 공백 포함/제외 값을 따로 낸다. 그림의 내용·한글 지면은 CER로 검증할 수 없다. 비교 파일은 개인 작업 폴더에 두고 공개 저장소에 커밋하지 않는다.
