# 한글 렌즈

시험지 사진을 브라우저에서 읽고 편집 가능한 HWPX로 저장합니다. 최종 글자·문서 배치 수정은 한글에서 합니다. 기존 포트폴리오의 /ocr/ 경로로 배포됩니다.

## 사용
1. JPG·PNG·WEBP 사진을 추가합니다. 최대 20장, 사진당 25MB입니다.
2. 필요할 때 변환 설정을 펼쳐 1단/2단을 선택합니다. 기본은 2단입니다.
3. 그림·그래프·가계도는 미리보기에서 영역을 지정합니다.
4. **한글 문서로 변환**을 누릅니다. 완료되면 같은 위치에 **HWPX 다운로드**가 표시됩니다.
5. 한글에서 문서를 열어 오인식과 최종 배치를 확인합니다.

사진은 서버로 전송하지 않습니다. 모델·엔진도 같은 사이트에서 제공합니다. 새로고침하면 작업이 사라지므로 먼저 HWPX를 저장해야 합니다. 변환 기록은 사진을 포함하지 않지만 인식된 글자는 포함합니다.

## 인식 처리
- Tesseract.js 7.0.0, kor+eng, WebAssembly / Web Worker.
- 업로드한 원본 바이트를 유지하며 JPEG로 재압축하지 않습니다. 인식 입력만 긴 변 4,400px 이하로 축소하고, 작은 입력은 확대하지 않습니다.
- 한국어 단어 간 공백 보존을 활성화합니다. 문자 내용이 같은 경우 엔진의 일반 텍스트 공백을 재사용합니다.
- 2단에서는 중앙 40~60% 구간의 공백 띠를 찾습니다. 얇은 단 구분선은 분석에서 제외합니다. 근거가 부족하면 50% 경계로 돌아가며 이 사실을 진단에 기록합니다.
- 문단 병합은 줄 사이 간격을 확인합니다. 그림을 가로질러 문장을 연결하지 않으며, 줄바꿈된 선지는 같은 문단으로 묶습니다.
- @로 읽힌 선지 시작은 문단을 분리하되 ①로 임의 교정하지 않습니다. 정답·문장 내용은 생성하거나 추측하지 않습니다.
- 회색조·대비·붉은 채점 흔적 완화는 OCR 입력에만 적용하고 지정한 그림은 원본 색을 유지합니다.

## 품질 검증과 피드백
변환 설정에서 **변환 기록 저장**을 누르면 파이프라인 버전, 원본 크기, 인식 글자·좌표, 문항 번호, 선지 기호 수, 그림 수, 단 경계를 JSON으로 저장합니다. 이것은 편집·복원용 프로젝트 파일이 아닙니다.

실제 원본을 사람이 확인한 기준 전사와 반복 비교하는 절차는 [QUALITY.md](QUALITY.md)에 기록합니다. 코드 회귀 검사, 실제 사진의 문자 정확도, 한글의 화면 배치는 별도 검증 항목입니다.

## 개발
저장소 루트에서 Node.js 24와 npm을 사용합니다.

~~~sh
npm ci
npm test
npm run dev
npm run build
~~~

Vercel은 **npm test && npm run build**를 실행합니다. 회귀 검사 실패 시 새 버전을 배포하지 않습니다. 기존 포트폴리오 파일과 경로는 유지합니다. 운영 환경 변수나 API 키는 필요 없습니다.

- web/app.js: 사진·그림 영역·변환 상태·HWPX와 진단 다운로드
- web/ocr.js: 전처리·단 경계·OCR·문단 구조
- web/hwpx.js: 텍스트·표·그림·미주를 포함한 실제 HWPX 생성
- web/template.json: 개인 정보와 문서 본문이 제거된 서식 정의
- tests/structure.mjs: 취소·읽기 순서·HWPX·표·그림·미주 검사
- tests/regressions.mjs: 단 경계·문단 분리·공백·CER 회귀 검사
- scripts/compare.mjs: 같은 원본의 개선 전후 변환 기록 비교

## 제한
사진의 원근·기울기, 검은 필기, 수식·분수, 작은 글자, 원형 선지 기호에는 오인식이나 누락이 남을 수 있습니다. 자동 그림 분리나 원본 지면 복제는 지원하지 않습니다. 회귀 검사 통과와 OCR 신뢰도는 실제 사진의 정확도를 보증하지 않습니다. 실제 한컴 한글 렌더링은 별도 확인이 필요합니다.

공개 예제는 코드로 만든 연습 문제입니다. 사용자의 원본 사진·문서·전사는 저장소나 사이트에 포함하지 않습니다.
