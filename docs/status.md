## 확인된 문제

- `tests/verify-structure.mjs`와 `styles/components/presentation.css`가 각각 300줄을 넘어 여러 책임을 한 파일에 포함한다.
- 여러 렌더러에 HTML 이스케이프 구현이 중복되고 PDF 서비스는 임시 DOM 구성과 내보내기 옵션을 함께 소유한다.
- 현재 세미나 데이터는 발표 슬라이드와 읽기 문서를 별도로 작성해 맥락과 세부 내용이 중복될 수 있으며 이미지 계약과 콘텐츠 분량 검증이 없다.
- 로컬 Chrome에서는 외부 CDN의 `html2pdf`가 로드되지 않아 직접 다운로드 대신 인쇄 fallback을 사용한다.
- Vercel CLI 58.4.4의 전이 의존성 감사 항목 30개는 상위 패키지 업데이트 시 재검토가 필요하다.

## 다음 작업

1. 일반 모듈화 작업은 200줄 권장·300줄 검토 기준으로 통합 테스트, 프레젠테이션 CSS, 공통 HTML 유틸리티와 PDF 책임부터 분리한다.
2. 새 채팅에서 세미나 작성 시스템 핸드오프를 검토한 뒤 공통 원본, 콘텐츠 계약, 에셋 명세와 검증 수준을 별도 설계로 확정한다.
3. 실제 배포를 시작할 때 Vercel Preview에서 정적 화면과 API를 검증한다.
4. 공개 운영을 시작하는 시점에 `main` 보호 및 배포 정책을 적용한다.

## 보류

- 세미나 작성 시스템의 정확한 콘텐츠 예산, 이미지 필수 메타데이터와 슬라이드·읽기 문서의 공통 원본 방식은 새 채팅의 설계 승인까지 보류한다.
- 외부에 공개된 기존 URL이 확인되면 호환 리다이렉트 정책을 다시 검토한다.
- 실제 Vercel Preview 생성은 외부 프로젝트 연결 권한이 필요한 배포 단계까지 보류한다.
