# Project Status

## 진행 중

- 세미나 도메인 패키지와 `introductory-60` 형식 설계 승인 및 테스트 우선 구현 계획 검토

## 확인된 문제

- 현재 세미나 데이터는 발표 슬라이드와 읽기 문서를 별도로 작성해 맥락과 세부 내용이 중복될 수 있으며 이미지 계약과 콘텐츠 분량 검증이 없다.
- 로컬 Chrome에서는 외부 CDN의 `html2pdf`가 로드되지 않아 직접 다운로드 대신 인쇄 fallback을 사용한다.
- Vercel CLI 58.4.4의 전이 의존성 감사 항목 30개는 상위 패키지 업데이트 시 재검토가 필요하다.

## 세미나 작성 시스템 설계

승인된 목표는 세미나 전용 데이터, UI, 레이아웃, 에셋, PDF·인쇄 기능, 스타일과 테스트를 `features/seminars/`가 소유하고 기존 `pages/`에는 URL 진입과 초기 조립만 남기는 것이다. 실제 비세미나 소비자가 있는 사이트 헤더, 공통 토큰·레이아웃과 범용 유틸리티만 전역에 유지한다.

첫 형식인 `introductory-60`은 관련 분야에 관심 있는 비전공자 일반인을 대상으로 한다. `문제의 정의 → 기존 접근 → 핵심 방법론 → 활용 사례 → 결론과 한계`를 내부 의미 구조로 사용하고 공개 제목은 쉽게 바꿀 수 있다. 핵심 방법론이 중심이지만 나머지 단계도 맥락을 위한 필수 요소다. `60분`은 대표 발표 상황일 뿐 정량적인 분량 제한이 아니며 하나의 구조화 원본에서 발표 자료와 독립적으로 읽히는 자료를 만든다.

현재는 설계가 승인되고 구현 계획을 작성한 상태다. 기존 `data/`, `components/`, `services/`, `styles/`와 `tests/`의 세미나 구현은 아직 이동하지 않았으며 구현 전까지 두 구조를 섞지 않는다. 상세 설계와 계획은 `docs/seminar-domain-design.md`, `docs/seminar-domain-plan.md`에 유지하고 이전이 끝나면 정규 문서에 흡수한 뒤 제거한다.

## 다음 작업

1. 구현 계획의 실행 방식을 선택한다.
2. 승인된 계획으로 `features/seminars/` 전체 이전과 두 기존 주제의 공통 원본 변환을 수행한다.
3. 실제 배포를 시작할 때 Vercel Preview에서 정적 화면과 API를 검증한다.
4. 공개 운영을 시작하는 시점에 `main` 보호 및 배포 정책을 적용한다.

## 보류

- 세미나 기능의 실제 파일 이전과 데이터 계약 구현은 설계 문서 검토 및 구현 계획 승인까지 보류한다.
- 외부에 공개된 기존 URL이 확인되면 호환 리다이렉트 정책을 다시 검토한다.
- 실제 Vercel Preview 생성은 외부 프로젝트 연결 권한이 필요한 배포 단계까지 보류한다.
